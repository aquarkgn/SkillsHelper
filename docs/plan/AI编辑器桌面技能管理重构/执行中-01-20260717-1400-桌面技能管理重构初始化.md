# AI编辑器桌面技能管理重构

## 用户需求

原始需求：参考 `farion1231/cc-switch` 的代码，使用最后一个发布 tag 作为参考并持续跟踪更新，彻底改造当前项目：建设 AI 编辑器的技能、MCP 工具、插件、CLI 命令扫描能力，以及中文本地化翻译工具；复用参考项目的桌面版架构、技术方案和前端页面样式，替换为 SkillHelper 自有 Logo；放弃当前项目的浏览器查看模式，改为左侧桌面版应用，但保留 Web 推广页面；品牌范围首期只实现 ChatGPT 与 Claude，其他编辑器标记为后续支持。

本次明确决策：不从零创建桌面应用。以 `cc-switch` 的最新发布版本作为可维护的代码基座，先清除其代理、供应商、流量统计等无关产品线，再把现有 SkillHelper 的扫描、命令说明、中文翻译设计迁入该基座。页面以参考项目现有组件、样式 Token、交互和布局为主，只替换 SkillHelper 品牌和新增必要的功能页面。

本机已确认安装 ChatGPT.app 与 Claude.app，并存在 `~/.claude`、Claude 应用数据目录、ChatGPT 应用数据目录和 `~/.codex`。这证明首期可从真实本机环境做发现测试；计划不得把 ChatGPT Desktop 与 Codex CLI 的配置语义混为一谈。

### 2. 锁定的实施策略：基座改造，不是重写

```text
cc-switch v3.9.1（完整桌面基座）
  ├── 保留：Tauri 壳、React 组件库、主题、国际化、设置、数据库迁移、技能/MCP 页面模式
  ├── 删除：代理、Provider、故障切换、用量、测速、代理深链与其数据表
  ├── 改造：App 导航、品牌、应用适配器、技能/MCP 域服务、SQLite schema
  └── 追加：插件扫描、CLI 命令扫描、中文翻译、ChatGPT/Claude 适配器、SkillHelper Logo
```

目标仓库结构以参考项目根目录为准：根目录采用其 `src/` 和 `src-tauri/`；保留 `packages/site/` 作为独立推广站；现有 `packages/web/` 不再演进为产品主界面。现有 `packages/scanner/` 与 `packages/server/` 是桌面端的业务真源：先通过本地 Node 桥接直接调用，并以其测试作为回归门禁；待发行版 sidecar 与 Rust 域服务逐项等价验证后，才允许替换运行实现。

这样做的边界是：不复制参考项目的品牌、文案或代理业务；保留其 MIT LICENSE；新功能只能以 SkillHelper 数据模型与 UX 需求驱动。首期不会创建第二套 React 页面或另起桌面工程。

### 4. SkillHelper 域模型与首期范围

桌面应用的左侧导航固定为：总览、技能、MCP 工具、插件、CLI 命令、中文翻译、设置。每个页面均按应用品牌筛选：ChatGPT、Claude、后续支持。

首期能力：

- 扫描 ChatGPT/Claude 的技能、MCP、插件和 CLI 命令，展示路径、来源、版本、解析状态与冲突。
- 默认只读扫描和中文展示；配置写入、安装、删除、启停必须在后续切片单独设计备份、回滚与确认交互。
- 中文翻译保留原文、机器译文、缓存状态和失败原因；沿用当前语言识别、MD5 缓存和代码段跳过规则作为回归基准。
- ChatGPT 与 Claude 采用统一 `EditorAdapter` 契约：应用发现、目录发现、配置解析、技能扫描、MCP 扫描、插件扫描、CLI 探测。后续编辑器只新增适配器，不在页面内增加品牌条件分支。
- ChatGPT Desktop 当前的本机目录仅证明应用存在，不等同于已验证 MCP/插件格式；相关页面先展示“未发现”或“格式待支持”，不能伪造功能可用。

不在首期：模型代理、Provider 管理、请求转发、计费、测速、故障切换、Codex/Gemini/Cursor 的实际扫描与写入。

### 5. 初始化改造任务

#### 阶段 A：建立可追踪基座

1. 在独立改造分支中导入 `cc-switch v3.9.1` 的完整树和 MIT 许可，记录上游 remote、tag、提交和本地差异策略。
2. 保留 `packages/site/`，将参考项目根目录的桌面工程作为新主应用；冻结当前 Web/Server/Scanner 的功能对照清单。
3. 先做可构建验证，再开始删除业务模块，避免在未知基座状态上重写 UI。

验收：可显示 SkillHelper 临时品牌的参考桌面壳，且不引入代理功能改动。

#### 阶段 B：代理产品线清理

1. 从 `src-tauri/src/lib.rs` 的 invoke 注册开始移除 Provider、Proxy、Failover、Usage、Stream Check 命令和状态管理。
2. 同步删除 Rust 服务、DAO、schema/migration、代理目录、前端 API、React Query、组件、导航、托盘项目和未使用依赖。
3. 保留并验证设置、国际化、文件选择、日志、窗口、单实例、更新器和技能/MCP 的通用基础。

验收：全局搜索不再有可调用的 proxy/provider/failover/usage 产品入口；应用可启动，设置页与通用 UI 正常。

#### 阶段 C：接入 SkillHelper 扫描语义

1. 从现有扫描器提取可测试规则：Claude Skills、Claude Agents、Claude Plugins、MCP 配置、插件清单、命令描述、品牌识别和路径去重。
2. 首期在 Tauri command 层通过本地 Node 桥接调用现有扫描器与翻译服务，不保留 Fastify HTTP 通讯层；后续再在参考项目已有 command/service/DAO 模式内增加可替换的 `catalog` 快照服务。
3. 优先迁移 Claude；ChatGPT 以真实目录与文件格式采样确定适配器，格式未确认的能力仅记录探测结果。
4. 为现有 Node 扫描结果建立脱敏 fixture，作为 Rust 迁移的逐项对比基线。

验收：一次扫描可在桌面端展示 Claude 的至少一种真实资产类型；结果与 fixture 对照可解释；扫描失败不影响其他类别。

#### 阶段 D：保留参考 UI 进行产品化改造

1. 复用参考项目的 UI 组件、Tailwind Token、主题、动效、表单、通知和技能/MCP 页面结构。
2. 将入口改成左侧桌面导航，移除 Provider 首屏、代理开关和应用切换的旧业务语义。
3. 仅替换 SkillHelper Logo、名称、中文文案、应用图标和目标页面信息结构；不制作平行的“全新设计系统”。
4. 后续支持的编辑器以禁用条目或“后续支持”状态显示，不伪装成可扫描品牌。

验收：核心页面视觉与交互继承参考项目，导航为 SkillHelper 信息架构，且无 cc-switch 可见品牌残留。

#### 阶段 E：翻译与命令能力迁入

1. 将现有 `langdetect`、翻译缓存、超时、局部失败和原文回退规则抽成可被 Fastify 与桌面桥接复用的模块；桌面扫描不自动翻译，用户主动翻译单条描述。发行版不得依赖常驻 Node/Fastify 服务，Node sidecar 的随包方案须在发布切片完成。
2. 迁入 Claude 的命令说明与本机 CLI 探测，并把命令运行限制为版本/帮助等只读白名单。
3. 建立翻译缓存迁移、敏感字段脱敏与离线失败 UX。

验收：技能、MCP、插件和 CLI 条目可独立显示中文说明；网络不可用时仍显示原文与明确状态。

#### 阶段 F：网页退出与发布准备

1. 在桌面端验收后停止 `packages/web` 的主产品定位，移除浏览器查看入口与本地服务启动依赖。
2. `packages/site` 只保留推广、下载和使用引导，链接到桌面应用，不承担扫描展示。
3. 增加安装包、升级、数据备份、异常日志、上游 tag 检查与差异评审流程。

验收：桌面应用可独立运行；推广站不依赖本地扫描服务；上游更新有记录、可评估、可拒绝同步。

### 6. 持续跟踪参考项目

- 固定 remote 名称 `cc-switch-upstream`，只跟踪 tags 和 release notes。
- 每次发现新 tag，记录：上游版本、变更模块、与 SkillHelper patch 的冲突、是否同步、同步测试结果。
- 优先同步安全、Tauri、依赖升级、通用 UI、设置、技能/MCP 通用缺陷；代理和 Provider 新功能默认不进入待同步范围。
- 本地改造集中在新领域目录和明确 patch 中，避免直接改散上游文件，从而保持未来 diff 可读。

### 7. 验证与门禁

- 基座：`pnpm tauri build`、前端 typecheck、Rust test、桌面启动、深浅色模式和窗口行为。
- 清理：编译器、全仓搜索和命令注册三重验证，没有残留代理、Provider、流量与故障切换链路。
- 扫描：Claude/ChatGPT 真实目录探测、无权限目录、空目录、损坏配置、重复条目、超大文件与路径变化。
- 中文化：中文短路、缓存命中/失效、代码段跳过、网络超时、部分翻译失败和原文回退。
- 质量：TypeScript strict、禁止 `any`/`@ts-ignore`、核心模块测试覆盖不低于 80%、`git diff --check`。

### 8. 方案修订：业务核心优先于参考代码

本次修订确认：`cc-switch` 可以作为根目录桌面基座导入，但它只提供 Tauri 壳、React 组件体系、主题、桌面交互和页面布局；不能替代 SkillHelper 的业务核心。

必须保留并接入当前项目的业务资产：

- `packages/scanner/`：按编辑器识别和扫描技能、MCP、插件、CLI 的规则、品牌识别、路径去重与测试。
- `packages/server/`：语言识别、翻译缓存、翻译失败回退、代码段跳过与测试。
- `packages/site/`：独立推广站。
- `packages/web/`：不再作为运行时浏览器主应用，但保留其现有业务字段、命令说明与交互测试，作为桌面页迁移的功能对照，直至对应桌面页验收完成。

目标页面不是参考项目原有的 Provider、技能市场或统一安装列表，而是：左侧“编辑器”选择 ChatGPT / Claude，主区域按当前编辑器显示“技能、MCP、插件、CLI”，详情页提供原文与中文翻译。参考项目组件只作为这些页面的视觉与交互容器。

### 9. 原地迁移步骤

1. 将已验证的 `codex/cc-switch-foundation` 分支切换到当前项目根目录，移除临时 worktree，不保留第二个最终代码目录。
2. 从当前工作树的可恢复快照中恢复 `packages/scanner/`、`packages/server/`、`packages/site/` 与计划文件；不再删除这三类核心业务资产。
3. 在 Tauri 命令层建立桌面桥接：首期直接调用现有 Node 扫描/翻译模块，返回当前 IR；迁移期间不再启动浏览器主应用或暴露 Fastify 页面。
4. 使用 `cc-switch` 的 Tailwind、通用组件和桌面外壳重写 `packages/web` 的展示层为 `src/` 桌面页，并以现有 Web 测试、扫描 fixture 和翻译测试验证字段与行为一致。
5. 仅删除参考项目自身的 Provider、代理、计费、测速、故障切换逻辑；不得删除 SkillHelper 的扫描、翻译、命令说明、品牌与推广站功能。

验收：Claude 的技能、MCP、插件、CLI 能通过桌面页按编辑器显示，并复用现有中文翻译缓存与回退行为；ChatGPT 页面先呈现真实可发现资产和格式待支持状态，不能用 Claude/Codex 语义冒充支持。
